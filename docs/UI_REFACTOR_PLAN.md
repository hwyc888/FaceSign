# FaceSign 后台 UI 重构实施说明

## 1. 重构目标

FaceSign 当前管理界面使用顶部横向按钮承载绝大多数功能，并且 `admin-ui.js` 在 `app.js` 之后再次定义 `renderShell()`，形成“旧壳层 + 新管理页覆盖”的结构。随着教师、班级、学生、课程、课程名单、课表、人脸设置等模块增加，顶部导航已经不适合继续扩展。

本轮只重构前端交互与视觉框架，原则上不改变现有 Go API、SQLite 数据结构、考勤判定逻辑和人脸识别业务逻辑。

最终目标：

- 采用标准后台管理界面：左侧功能菜单 + 右侧工作区。
- 顶部只保留系统名称、服务状态、当前用户和退出。
- 左侧菜单支持展开/收起，收起后显示图标并保留 tooltip。
- 右侧每个页面统一使用“页面标题 + 操作栏 + 内容区”的结构。
- 管理员和教师按角色显示不同菜单。
- 桌面端优先，同时保持手机/平板响应式。
- 不再使用顶部横向功能按钮和管理页内部二级横向 Tabs 作为主导航。
- 页面切换不整页刷新，继续使用现有单页式 JS 路由状态。
- 所有成功、警告、失败提示统一中文样式。

## 2. 当前问题定位

### 2.1 壳层重复

当前 `internal/webui/assets/app.js` 和 `internal/webui/assets/admin-ui.js` 都定义了 `renderShell()`；后加载的 `admin-ui.js` 实际覆盖前者。该方式容易出现后续开发人员修改错文件、事件重复绑定和页面状态不一致的问题。

重构后要求：

- 全项目只保留一个 `renderShell()`。
- 壳层、侧边栏、页头、内容区由一个布局模块统一负责。
- 管理员功能不再通过覆盖 `renderShell()` 注入。

### 2.2 导航层级混乱

当前管理员顶部直接同时出现实时考勤、教师、班级、学生、课程、课程名单、课表、人脸识别、请假、刷脸终端和退出；管理页面内部又有一套 `admin-tabs`。

重构后主导航只能有一套：左侧菜单。

### 2.3 内容页面样式不统一

当前部分页面为 Card，部分页面为表格，新增表单直接放在内容顶部，设置页又采用不同布局。需要统一页面骨架和 CRUD 交互。

## 4. 左侧菜单设计

### 4.1 管理员菜单

#### 考勤业务
- 实时考勤
- 请假管理
- 刷脸终端

#### 基础资料
- 教师管理
- 班级管理
- 学生管理
- 课程管理
- 课程名单
- 课表管理

#### 系统管理
- 人脸识别
- 服务状态
- 系统设置

### 4.2 教师菜单

教师不显示基础资料维护和系统设置。

#### 考勤业务
- 实时考勤
- 请假管理
- 刷脸终端

如果以后增加“我的课程 / 我的课表”，再放入教师菜单，不提前制造空页面。

### 4.3 侧边栏交互

- 默认宽度 232px。
- 收起宽度 68px。
- 展开状态显示图标 + 文本。
- 收起状态只显示图标，鼠标悬停显示中文 tooltip。
- 当前页面必须明显高亮。
- 刷新页面后默认恢复到最近一次使用的展开/收起状态，使用 `localStorage` 保存，不存任何登录凭据。
- 左侧菜单固定高度 `100vh`，右侧内容独立滚动，解决长表格滚动后菜单消失问题。

## 5. 顶部栏设计

顶部栏不再承担业务导航，只显示：

- 左侧：当前页面标题或系统名称。
- 中间/右侧：FaceSign 服务状态、人脸引擎状态。
- 当前登录用户姓名与角色。
- 退出登录。

状态建议：

- 绿色圆点：正常。
- 黄色圆点：配置不完整/降级。
- 红色圆点：服务异常。

顶部高度建议 60~64px，固定在右侧内容区顶部。

## 6. 右侧页面统一规范

每个页面均采用同一骨架：

```text
页面标题
页面简短说明                         [主要操作]
-------------------------------------------------
筛选栏 / 搜索栏 / 状态筛选
-------------------------------------------------
统计卡片（有需要时）
-------------------------------------------------
表格 / 卡片 / 设置表单
```

统一要求：

- 新增操作：右上角主按钮。
- 新增/编辑：Dialog 或右侧 Drawer，不在列表顶部长期展开大表单。
- 删除：二次确认。
- 空数据：显示明确的中文空状态及下一步操作按钮。
- 加载：统一 Skeleton / Loading。
- API 失败：内容区域显示错误卡，同时保留“重试”按钮。
- 成功：右上角 Toast，3 秒自动消失。
- 表格操作列固定靠右。
- 按钮等级统一：主要、普通、危险。

## 7. 各功能页面详细布局

### 7.1 实时考勤

页面顶部：

- 当前课程数
- 准时人数
- 迟到人数
- 请假人数
- 旷课人数
- 未签到人数

课程区域使用卡片或紧凑列表，点击课程后右侧/下方展示学生考勤明细。

学生考勤表：

- 学号
- 姓名
- 班级
- 状态
- 签到时间
- 人脸相似度
- 操作

人工修改状态继续使用现有 API，UI 改为统一下拉/操作菜单，避免每行放 4 个大按钮。

### 7.2 请假管理

将现在的“登记请假”顶部按钮改成独立页面。

页面内容：

- 搜索学生
- 班级筛选
- 时间范围
- 请假状态
- 新增请假按钮
- 请假记录表

新增请假使用 Dialog。

### 7.3 刷脸终端

左侧菜单点击后可以：

- 在当前页面显示终端说明与服务状态；
- 提供“进入刷脸终端”主按钮打开 `/kiosk`；
- 显示人脸引擎是否可用、摄像头要求、HTTPS 提示。

不把 `/kiosk` 的大摄像头界面硬塞进后台内容区，避免后台和终端用途混杂。

### 7.4 教师管理

顶部：

- 搜索教师
- 状态筛选
- 新增教师

表格：

- 姓名
- 用户名/工号
- 状态
- 创建时间
- 操作

新增/编辑统一 Dialog。

### 7.5 班级管理

表格：

- 班级名称
- 学生人数
- 状态
- 操作

点击班级可进入班级详情或打开 Drawer 显示班级学生。

### 7.6 学生管理

顶部工具栏：

- 班级筛选
- 姓名/学号搜索
- 人脸状态筛选
- 新增学生

表格：

- 学号
- 姓名
- 班级
- 状态
- 人脸录入状态
- 操作

“采集人脸”作为行级操作。点击前继续先检测人脸服务状态；不可用时直接中文提示，不打开摄像头。

### 7.7 课程管理

表格：

- 课程名称
- 任课教师
- 已选学生人数（API 有数据时显示）
- 状态
- 操作

新增课程使用 Dialog。

### 7.8 课程名单

推荐做成左右子布局：

```text
┌──────────────────┬─────────────────────────────────────┐
│ 课程列表          │ 当前课程：数据库基础                 │
│                  │ 学生搜索 / 班级筛选 / 添加学生        │
│ 数据库基础  46人  │ ---------------------------------- │
│ C#程序设计  42人 │ 当前课程学生名单                      │
│ Python      44人 │                                     │
└──────────────────┴─────────────────────────────────────┘
```

支持：

- 选择课程。
- 查看完整名单。
- 按班级过滤可添加学生。
- 添加学生。
- 移出课程。
- 显示人数。

### 7.9 课表管理

默认采用周课表视图，而不是只显示普通表格。

桌面布局：

- 横轴：周一 ~ 周日。
- 纵轴：时间段/节次。
- 每个课程块显示课程、教师、教室、时间。

同时保留“列表视图”，用于编辑和删除。

筛选项：

- 教师
- 课程
- 教室
- 星期

### 7.10 人脸识别设置

分成 3 张设置卡：

#### 引擎配置
- 停用 / 本地原生 CPU / CompreFace
- 服务地址
- API Key（仅 CompreFace）
- 相似度阈值
- 检测阈值

#### 服务状态
- 服务是否可达
- 当前设备：CPU
- GPU 是否需要：否
- 已录入人数/样本数（接口能提供时）
- 检测服务按钮

#### 部署说明
- Windows 原生服务
- Linux systemd
- 数据目录
- 迁移说明

设置页不显示一大段开发说明，技术细节放折叠的“部署与维护说明”。

### 7.11 服务状态

新增独立页面，集中显示：

- FaceSign Web 服务
- SQLite 数据库
- 人脸引擎
- SSE 实时事件
- 当前服务版本
- 系统运行时长（后端增加接口后再显示）

初版可以先复用现有可检测的信息，不为了 UI 强行改大量后端。

### 7.12 系统设置

初版只放已有可配置项。没有后端支持的设置不要做假按钮。

后续可逐步加入：

- 学校/系统名称
- 默认时区
- 默认迟到宽限时间
- 考勤提前开放分钟数
- 数据备份
- HTTPS 状态

## 8. 前端代码拆分方案

当前项目不需要为了 UI 重构立即引入 Vue/React/Node 构建链，继续保持 Go `embed` 静态资源方式，减少部署依赖。

建议拆分为：

```text
internal/webui/assets/
  index.html
  styles/
    tokens.css
    base.css
    layout.css
    components.css
    pages.css
    responsive.css
  js/
    app.js
    api.js
    state.js
    layout.js
    sidebar.js
    router.js
    toast.js
    dialogs.js
    pages/
      dashboard.js
      leave.js
      teachers.js
      classes.js
      students.js
      courses.js
      enrollment.js
      schedules.js
      face-settings.js
      service-status.js
      system-settings.js
      kiosk-entry.js
```

如果当前 Go `embed` 规则只嵌入固定文件，需要同步修改 `embed` 路径为递归资源目录。

## 9. 状态与路由设计

使用轻量页面状态，不引入前端框架：

```js
state = {
  me,
  view,
  sidebarCollapsed,
  filters,
  selectedCourseID,
  selectedSessionID
}
```

`showView(view)` 作为唯一页面切换入口。

要求：

- 页面切换时更新左侧 active 状态。
- 不重复创建 SSE。
- Dashboard timer 只在 Dashboard 工作。
- 页面离开时清理当前页面临时事件。
- 不再通过重复定义全局函数覆盖功能。

## 10. CSS 设计规范

建议使用 CSS Variables 统一设计 Token：

```css
--sidebar-width: 232px;
--sidebar-collapsed-width: 68px;
--topbar-height: 64px;
--content-bg: #f5f7fb;
--surface: #ffffff;
--border: #e5e7eb;
--text: #111827;
--muted: #6b7280;
--primary: #2563eb;
--danger: #dc2626;
--success: #16a34a;
--radius: 10px;
```

原则：

- 后台界面减少大圆角和夸张渐变。
- 卡片圆角 8~12px。
- 左侧使用深色或深蓝灰背景。
- 右侧使用浅灰背景 + 白色内容卡。
- 表格行高保持紧凑。
- 同一级按钮尺寸统一。
- 不手工给每个页面写 inline style。

## 11. 响应式要求

### >= 1200px
- 左侧默认展开。
- 右侧完整表格。

### 768px ~ 1199px
- 左侧可默认收起为图标模式。
- 右侧内容保持正常。

### < 768px
- 左侧菜单改为抽屉 Drawer。
- 顶部出现菜单按钮。
- 表格根据页面改为卡片或允许必要的局部横向滚动。
- 不允许整个页面产生横向滚动。

刷脸终端 `/kiosk` 保持单独的终端响应式布局，不强制套后台侧栏。

## 13. 必须保留的业务行为

UI 重构不得破坏：

- SQLite 现有数据。
- 教师/管理员权限。
- 实时考勤 SSE。
- 准时/迟到/请假/旷课判定。
- 重复刷脸保留最早有效签到。
- 教师人工修正优先。
- 人脸录入前服务检测。
- 无人脸服务时中文提示。
- Windows/Linux 原生 CPU 人脸引擎。
- `/kiosk` 原有刷脸逻辑。

## 14. 验收清单

1. 登录后不再看到顶部一长排功能按钮。
2. 左侧菜单完整、清晰、有分组。
3. 左侧可收起为图标模式，并能再次展开。
4. 右侧标题和菜单选择一致。
5. 管理员和教师看到的菜单符合权限。
6. 滚动长列表时左侧菜单始终可用。
7. 教师、班级、学生、课程、课程名单、课表全部可操作。
8. 空数据页面不报 JS 错误。
9. 人脸服务未运行时学生采集不会先打开摄像头。
10. 实时考勤 SSE 正常刷新。
11. `/kiosk` 独立正常运行。
12. 手机、平板、PC 均不出现整体横向滚动。
13. 浏览器 Console 无未捕获异常。
14. `go test ./...`、`go vet ./...` 通过。
15. Windows/Linux 发布包构建成功。

## 15. 本轮禁止事项

- 不为 UI 重构更换 SQLite。
- 不引入 Docker、Python 或新的服务器运行时。
- 不把全部前端继续堆进单个 `app.js`。
- 不同时保留顶部主导航和左侧主导航两套入口。
- 不做没有后端支持的“假设置”。
- 不因重构修改考勤评分/判定规则。
- 不删除或重建现有数据库。

## 16. 建议实施顺序

先完成阶段 A 的壳层并保证所有旧页面仍可进入，再逐页迁移。不要一次性重写全部页面后才测试。

推荐提交拆分：

1. `refactor(ui): introduce sidebar application shell`
2. `refactor(ui): migrate academic management pages`
3. `refactor(ui): redesign attendance and leave pages`
4. `refactor(ui): redesign face and service settings`
5. `test(ui): validate responsive shell and production build`

这样任一阶段出现问题都容易定位和回滚。
